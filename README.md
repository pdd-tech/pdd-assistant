# pdd-assistant

RAG-помощник по правилам дорожного движения для учеников автошколы.

Ученик задаёт вопрос своими словами и получает ответ со ссылками на пункты ПДД и статьи главы 12 КоАП РФ. Нужные документы находит собственный поисковый индекс BM25, а ответ по ним формулирует LLM. Админ (сотрудник автошколы) заводит учеников и смотрит журнал их запросов.

## Запуск КТ2 на localhost

Установите Go 1.25+ и [Ollama](https://ollama.com/download). Все команды выполняются из корня проекта. После скачивания модель занимает около 7–8 ГБ на диске и работает локально. На Mac с Apple Silicon и 24 ГБ памяти контекст 8192 токена и Ollama 0.40.13 дали прогрев около 5 секунд и финальный прогон за 1 минуту 36 секунд. Для прогона по умолчанию используется быстрый режим `LLM_DISABLE_REASONING=true`. Для демонстрации заранее скачайте модель и дайте первый запрос на прогрев. Оставьте Ollama запущенным на время показа. [Модель Qwen 3.5 9B](https://ollama.com/library/qwen3.5:9b)

### macOS и Linux

В терминале A запустите Ollama. Если Ollama уже запущен, используйте действующий сервер на `127.0.0.1:11434` с контекстом от 8192 токенов.

```sh
OLLAMA_HOST=127.0.0.1:11434 OLLAMA_NO_CLOUD=1 OLLAMA_CONTEXT_LENGTH=8192 ollama serve
```

В терминале B скачайте и прогрейте модель, проверьте проект и поднимите сервер.

```sh
ollama pull qwen3.5:9b
ollama run qwen3.5:9b --think=false "Ответь одним словом: готов"
go test ./...
export ADMIN_LOGIN=admin
printf 'Пароль локального администратора: '
read -rs ADMIN_PASSWORD
printf '\n'
export ADMIN_PASSWORD
go run ./cmd/server
```

### Windows (PowerShell)

Если Ollama запустился в трее после установки, выйдите из него. В терминале A запустите Ollama с нужными параметрами.

```powershell
$env:OLLAMA_HOST = "127.0.0.1:11434"
$env:OLLAMA_NO_CLOUD = "1"
$env:OLLAMA_CONTEXT_LENGTH = "8192"
ollama serve
```

В терминале B скачайте и прогрейте модель, проверьте проект и запустите сервер.

```powershell
ollama pull qwen3.5:9b
ollama run qwen3.5:9b --think=false "Ответь одним словом: готов"
go test ./...
$env:ADMIN_LOGIN = "admin"
$env:ADMIN_PASSWORD = [System.Net.NetworkCredential]::new("", (Read-Host "Пароль локального администратора" -AsSecureString)).Password
go run ./cmd/server
```

### Проверка приложения

Откройте точный адрес `http://127.0.0.1:<порт>` из вывода сервера. Войдите админом, создайте ученика, выйдите и войдите под учеником. Спросите «Можно ли обгонять на мосту?» и раскройте источники. Войдите обратно админом и найдите вопрос в журнале. После перезапуска пользователи и журнал сохраняются в `pdd-assistant.sqlite`, войти нужно заново.

Настройки читаются из окружения. Для локальной модели ключ не требуется. Значения по умолчанию и все переменные приведены в [архитектуре](spec/tech/architecture.md#настройки) и [.env.example](.env.example). Если используете файл `.env`, Go сам его не читает. В macOS/Linux перед запуском экспортируйте значения командами `set -a`, `. ./.env`, `set +a` из корня проекта. В PowerShell задавайте значения через `$env:ИМЯ = "значение"`. Пароль существующего админа при перезапуске сохраняется.

## Benchmark на КТ2

Команды для терминала C одинаковы в macOS/Linux и PowerShell.

```sh
go run ./cmd/bench -mode retrieval -out tmp/kt2-retrieval.json
go run ./cmd/bench -mode rag -out tmp/kt2-live.json
go run ./cmd/bench -mode score -run tmp/kt2-live.json -out tmp/results.md
```

`retrieval` работает без модели. `rag` делает 15 живых запросов через тот же RAG-сервис, который вызывает HTTP-сервер. В JSON сохраняются ответы, фактический контекст `sources`, полный рейтинг `hits` и время. При ошибках прогона CLI возвращает ненулевой код, а `score` отклоняет такой файл.

Для Accuracy и Correct Rejection Rate ответственный за оценку сверяет все 15 ответов по [чек-листу приёмки](docs/KT2-ACCEPTANCE.md#приёмка-benchmark-и-ручная-оценка) и сохраняет оценки с `run_id` и SHA256 файла прогона. SHA256 выдаёт `shasum -a 256 tmp/kt2-live.json` на macOS/Linux или `(Get-FileHash tmp/kt2-live.json -Algorithm SHA256).Hash.ToLowerInvariant()` в PowerShell. Затем пересчитайте отчёт.

```sh
go run ./cmd/bench -mode score -run tmp/kt2-live.json -grades tmp/grades.json -out tmp/results.md
```

Recall@5 и MRR автоматически считаются по десяти обычным вопросам, глубина MRR — полная выдача (до 30 документов). Это параметры плана команды, их нужно подтвердить с преподавателем. Accuracy и CRR до ручной оценки отображаются как «не оценено». На защите снова запускаем `rag` и оцениваем полученные ответы.

Исходный и финальный прогоны, их оценки и разбор ошибок связаны в [отчёте benchmark](benchmark/results.md).

## Просмотр интерфейса

`go run ./cmd/ui-preview` открывает экран входа и демонстрационные состояния по адресу из вывода команды. Для живого прохода с SQLite, BM25 и моделью используйте `cmd/server`.

## Как открыть прототип

Прототип интерфейса — статичные HTML-страницы, сервер не нужен.

1. Склонировать репозиторий: `git clone https://github.com/pdd-tech/pdd-assistant.git`
2. Открыть в браузере файл `prototype/index.html`.

На экране входа логин `admin` открывает экраны админа, любой другой логин — экраны ученика. Пароль любой.
