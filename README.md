# pdd-assistant

RAG-помощник по правилам дорожного движения для учеников автошколы.

Ученик задаёт вопрос своими словами и получает ответ со ссылками на пункты ПДД и статьи главы 12 КоАП РФ. Нужные документы находит собственный поисковый индекс BM25, а ответ по ним формулирует LLM. Админ (сотрудник автошколы) заводит учеников и смотрит журнал их запросов.

## Запуск КТ2 на localhost

Нужны Go 1.25+, интернет и **Authorization key GigaChat API** из [кабинета Studio](https://developers.sber.ru/studio/workspaces/my-space/get/gigachat-api). Создайте проект для физического лица на тарифе Freemium. Основная модель — `GigaChat-2-Max`. Она присутствует в списке моделей предоставленного ключа; для Max есть выданная квота. Используем действующий официальный адрес Сбера, который доступен из этой сети. Покупать пакеты приложение не будет.

Скопируйте `.env.example` в `.env`, если своего файла ещё нет, и задайте `GIGACHAT_CREDENTIALS`. Это Authorization key, а не временный Access token: приложение само получает и обновляет токен OAuth. Существующий `.env` не перезаписывайте; при смене профиля перенесите LLM-настройки из примера, сохранив свои данные. Ключи Google и OpenRouter для GigaChat не используются. `.env` исключён из Git, Go сам его не загружает.

Проверка TLS включена. Публичный корневой сертификат из официальной инструкции находится в `certs/` и используется только клиентом GigaChat. Устанавливать сертификат в систему, отключать TLS или скачивать веса модели не нужно.

### macOS и Linux

Из корня проекта загрузите локальную конфигурацию. Пароль администратора можно задать в `.env` либо ввести в терминале без отображения:

```sh
set -a
. ./.env
set +a
export ADMIN_LOGIN=admin
printf 'Пароль локального администратора: '
read -rs ADMIN_PASSWORD
printf '\n'
export ADMIN_PASSWORD
go test ./...
go run ./cmd/llm-check
go run ./cmd/server
```

### Windows PowerShell

Загрузка простых строк `ИМЯ=значение` из `.env`, затем ввод пароля и запуск:

```powershell
Get-Content .env | ForEach-Object {
    if ($_ -match '^([A-Z_]+)=(.*)$') {
        [Environment]::SetEnvironmentVariable($Matches[1], $Matches[2], "Process")
    }
}
$env:ADMIN_LOGIN = "admin"
$env:ADMIN_PASSWORD = [System.Net.NetworkCredential]::new("", (Read-Host "Пароль локального администратора" -AsSecureString)).Password
go test ./...
go run ./cmd/llm-check
go run ./cmd/server
```

### Квота и проверка API

`llm-check` проверяет OAuth и список моделей, затем делает настоящий запрос на вымышленных правилах: при задержке 13 минут правильный ответ — сбор 25 условных единиц, пропуск сдают дежурному на выезде. Смысл ответа нужно проверить отдельно. При ошибке этой команды сначала устраните причину, затем запускайте benchmark.

Freemium и остаток пакета проверяйте в кабинете Studio; программа не покупает токены и не подключает платный тариф. Обычно вопрос требует одного вызова генерации, максимум двух при исправлении структуры или цитат. Полный benchmark — обычно 15, максимум 30 вызовов; OAuth кэшируется в памяти. Дополнительный проход проверки можно включить через `LLM_VERIFY_ANSWER=true`, но это увеличивает расход и не заменяет оценку человеком.

При OAuth 401 проверьте Authorization key и Scope, при 429 — квоту, при 503 — доступность сервиса. Сетевая ошибка не считается содержательным отказом. Сервер и CLI используют один профиль и одинаковые промпты. Не задавайте вопросы в браузере одновременно с benchmark.

### Проверка приложения

Откройте точный адрес `http://127.0.0.1:<порт>` из вывода сервера после успешного открытия порта. По умолчанию ОС выбирает свободный порт; не используйте произвольный старый localhost. Войдите админом, создайте ученика, выйдите и войдите под учеником. Спросите «Можно ли обгонять на мосту?» и раскройте источники. Войдите обратно админом и найдите вопрос в журнале. После перезапуска пользователи и журнал сохраняются в `pdd-assistant.sqlite`, войти нужно заново. Пароль существующего админа сохраняется.

Все переменные описаны в [архитектуре](spec/tech/architecture.md#настройки). Для другого совместимого API адрес и имя модели задаются явно. Основной профиль не требует локального сервера модели; на компьютере работает только наше приложение.

## Benchmark на КТ2

Откройте второй терминал и загрузите **тот же `.env`** способом для вашей ОС выше. Пароль администратора для benchmark не требуется. Команды одинаковы в macOS/Linux и PowerShell.

```sh
go run ./cmd/bench -mode retrieval -out tmp/kt2-retrieval.json
go run ./cmd/bench -mode rag -out tmp/kt2-live.json
go run ./cmd/bench -mode score -run tmp/kt2-live.json -out tmp/results.md
```

`retrieval` работает без модели. `rag` делает 15 живых запросов через тот же RAG-сервис, который вызывает HTTP-сервер. В JSON сохраняются ответы, фактический контекст `sources`, полный рейтинг `hits` и время. При ошибках прогона CLI возвращает ненулевой код, а `score` отклоняет такой файл.

Для Accuracy и Correct Rejection Rate ответственный за оценку сверяет все 15 ответов по [чек-листу приёмки](docs/KT2-ACCEPTANCE.md#приёмка-benchmark-и-ручная-оценка) и сохраняет оценки с `run_id` и SHA256 файла прогона. SHA256 выдаёт `shasum -a 256 tmp/kt2-live.json` на macOS/Linux или `(Get-FileHash tmp/kt2-live.json -Algorithm SHA256).Hash.ToLowerInvariant()` в PowerShell. Затем пересчитайте отчёт.

```sh
go run ./cmd/bench -mode score -run tmp/kt2-live.json -grades tmp/grades.json -out tmp/results.md
```

Recall@5 и MRR автоматически считаются по десяти обычным вопросам, глубина MRR — полная выдача (до 30 документов). Это параметры плана команды, их нужно подтвердить с преподавателем. Accuracy и CRR до ручной оценки отображаются как «не оценено». На защите снова запускаем `rag` и оцениваем полученные ответы.

Последний реальный прогон GigaChat-2-Max от 21.11.2026 охватил все 15 вопросов. Результаты, заполненный бланк, исходные ответы и разбор четырёх ошибок проверки цитат (E4) собраны в [отчёте benchmark](benchmark/results.md).

## Просмотр интерфейса

`go run ./cmd/ui-preview` открывает экран входа и демонстрационные состояния по адресу из вывода команды. Для живого прохода с SQLite, BM25 и моделью используйте `cmd/server`.

## Как открыть прототип

Прототип интерфейса — статичные HTML-страницы, сервер не нужен.

1. Склонировать репозиторий: `git clone https://github.com/pdd-tech/pdd-assistant.git`
2. Открыть в браузере файл `prototype/index.html`.

На экране входа логин `admin` открывает экраны админа, любой другой логин — экраны ученика. Пароль любой.
