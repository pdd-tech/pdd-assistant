# Правила репозитория

Эти правила общие для всех кодинговых агентов и людей, которые работают с проектом.

## Перед изменением кода

1. Прочитай `spec/product/` и `spec/tech/`.
2. Сначала обнови нужную спецификацию, потом меняй код. Код не должен расходиться с документацией.
3. Запусти тесты (`go test ./...`) и, если менялся поиск, benchmark (см. `spec/tech/rag.md`).
4. Добавь строку в `CHANGE_HISTORY.md`.

## Ограничения

- Делаем только то, что описано в `spec/`. Новую функциональность сначала добавляем в спецификацию и обсуждаем с командой.
- Поисковый индекс BM25 пишем сами. Готовые поисковые движки (Elasticsearch, Bleve, Meilisearch и т.п.) использовать нельзя.
- Ключи API и пароли не попадают в репозиторий. Они передаются только через переменные окружения (см. `spec/tech/architecture.md`).
- Документация пишется на русском языке.

## Git

1. Перед началом задачи обнови `main` (`git pull`) и создай от него ветку: `docs/<тема>` для документации, `feat/<тема>` для кода и интерфейса.
2. В ветке коммить со своего аккаунта. Сообщение коммита пишется на русском в повелительном наклонении: «Добавить …», «Описать …».
3. В той же ветке добавь строку в `CHANGE_HISTORY.md` в формате `- ДД.ММ.ГГГГ: что сделано.`
4. Запушь ветку и открой Pull Request в `main`. Напрямую в `main` не пушим.
5. После слияния PR начинай следующую задачу с шага 1.
