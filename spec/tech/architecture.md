# Архитектура

## Стек

| Что | Чем | Почему |
|---|---|---|
| Язык и веб-сервер | Go 1.25+, стандартная библиотека `net/http` | Команда знает Go; для нескольких страниц сторонний фреймворк не нужен |
| Интерфейс | HTML-страницы, которые сервер отрисовывает через `html/template` | Один бинарник, нет отдельной сборки фронтенда. Шаблоны и ресурсы встроены в `internal/ui` |
| База данных | SQLite, драйвер `modernc.org/sqlite` | Один файл, не нужен отдельный сервер БД. Драйвер на чистом Go и собирается без C-компилятора, в том числе на Windows |
| Хеширование паролей | `golang.org/x/crypto/bcrypt` | Пароли не хранятся в открытом виде |
| Поиск | Свой индекс BM25 | Требование методички. Подробности в `spec/tech/rag.md` |
| LLM | Бесплатный внешний API OpenRouter с NVIDIA Nemotron 3.5 Super VL | См. раздел «LLM» |

## Компоненты

```
браузер
   │
   ▼
  web ── auth (сессии)
   ├──── store (SQLite: users, query_log)
   └──── rag ── search (BM25, корпус из corpus/)
          │  └─ llm (HTTP-клиент)
          ▲
       cmd/bench
```

- **web** — обработчики HTTP и шаблоны страниц.
- **auth** — сессии и CSRF. Web проверяет роль, store проверяет логин и пароль. Сессия — случайный идентификатор в cookie, сессии хранятся в памяти процесса. После перезапуска сервера нужно войти заново.
- **store** — работа с SQLite: пользователи и журнал запросов.
- **search** — предобработка текста, индекс BM25 и поиск top-k документов. Индекс строится в памяти при запуске сервера из файлов корпуса. Подробности в `spec/tech/rag.md`.
- **rag** — общий сервис для веб-интерфейса и CLI. Один поиск даёт полную ранжированную выдачу для MRR и первые k документов для модели.
- **llm** — формирует промпт из вопроса и найденных документов и получает ответ модели.

## Путь запроса

1. Ученик отправляет вопрос со страницы вопроса.
2. **web** проверяет через **auth**, что пользователь вошёл и у него роль `student`.
3. **web** проверяет форму и записывает допустимый вопрос в `query_log` через **store**.
4. **rag** получает выдачу **search** и выделяет top-k документов. Значение k задано в `spec/tech/rag.md`.
5. Если есть совпадения, **llm** передаёт модели инструкцию, top-k документов с номерами пунктов и вопрос.
6. **web** показывает ответ или отказ модели и список найденных документов.

Если модель не ответила, ученик видит найденные документы и сообщение, что ответ получить не удалось.

## Страницы

| Адрес | Метод | Роль | Что делает |
|---|---|---|---|
| `/login` | GET, POST | все | Форма входа, вход |
| `/logout` | POST | все | Выход |
| `/` | GET | student | Форма вопроса |
| `/ask` | POST | student | Ответ и найденные документы |
| `/admin/users` | GET | admin | Список учеников и форма создания |
| `/admin/users` | POST | admin | Создание ученика |
| `/admin/log` | GET | admin | Журнал запросов |

После входа ученик попадает на `/`, админ на `/admin/users`. Экраны описаны в `spec/product/scenarios.md`.

## База данных

### `users`

| Поле | Тип | Описание |
|---|---|---|
| `id` | INTEGER, PK | |
| `login` | TEXT, UNIQUE, NOT NULL | Логин |
| `password_hash` | TEXT, NOT NULL | Хеш пароля bcrypt |
| `role` | TEXT, NOT NULL | `admin` или `student` |
| `created_at` | DATETIME, NOT NULL | Когда создан |

### `query_log`

| Поле | Тип | Описание |
|---|---|---|
| `id` | INTEGER, PK | |
| `user_id` | INTEGER, NOT NULL, FK → `users.id` | Кто спросил |
| `question` | TEXT, NOT NULL | Текст вопроса |
| `created_at` | DATETIME, NOT NULL | Когда спросил |

Первый админ создаётся при запуске из `ADMIN_LOGIN` и `ADMIN_PASSWORD`. Пароль существующего админа сохраняется. Если указанный логин принадлежит ученику, запуск завершается ошибкой. Логин — от 1 до 64 Unicode-символов без внутренних пробельных и управляющих символов (краевые пробелы обрезаются). Пароль — до 72 байт, с минимум одним непробельным символом. База проверяет внешние ключи; ученики и журнал отсортированы от новых к старым.

## LLM

Клиент отправляет запрос на `POST {LLM_BASE_URL}/chat/completions`. Основной профиль — OpenRouter, `https://openrouter.ai/api/v1`, конкретная модель `nvidia/nemotron-3.5-super-vl:free`. Ollama и скачивание модели не нужны. Обязателен `LLM_API_KEY`, который передаётся только как Bearer. Для OpenRouter разрешены только HTTPS, стандартный адрес API и ID с суффиксом `:free`; автоматического перехода на платную модель нет. Перед сдачей проверить доступность выбранного ID в каталоге и остаток лимита аккаунта. При отсутствии ключа запуск сообщает об ошибке до обращения к API.

Модель получает только вопрос и top-k источников с `id`, `ref` и текстом. Для полного ответа возвращает `refused=false` и массив `parts`: каждый элемент содержит вывод `text`, ID `source` и массив дословных цитат `quotes`, подтверждающих вывод. Клиент проверяет ID, непустые цитаты и их вхождение в соответствующий исходный документ с нормализацией пробелов. Ссылки подставляются из корпуса. Цитата сама по себе не доказывает правильность вывода: семантика и применимость нормы дополнительно проверяются моделью и при оценке benchmark.

При `LLM_VERIFY_ANSWER=true` второй вызов той же модели проверяет черновик по исходному вопросу и тем же документам: покрытие подвопросов, основания, условия, исключения, расчёты и диапазоны чисел. Он возвращает исправленный полный ответ в той же структуре либо отказ. Ответ ученику берётся только из успешно проверенного второго результата. Если проверка недоступна, приложение показывает ошибку сервиса и сохраняет источники, не публикует непроверенный черновик. Проверка модели не является гарантией правильности и не заменяет оценку человеком.

При нехватке данных модель возвращает `refused=true`, пустой `parts` и пояснение `missing`; частичные выводы не публикуются. При нарушении JSON, цитат или лимите генерации допускается один дополнительный запрос исправления на весь цикл генерации и проверки. Максимум три HTTP-вызова на вопрос при включённой проверке, два без неё. Все вызовы и ожидания входят в общий `LLM_TIMEOUT`. Сетевые ошибки и HTTP 401/402/429/5xx возвращаются без автоматических повторов и не считаются корректным отказом.

В основном профиле отправляется `response_format={"type":"json_object"}`: выбранный endpoint поддерживает JSON-объект. Клиент независимо проверяет структуру и цитаты. Для несовместимого API задать `LLM_JSON_MODE=false`. Для OpenRouter при отключённом рассуждении передаётся `reasoning={"enabled":false}`; для другого совместимого API — `reasoning_effort=none`. Минимальный интервал между началами вызовов одного клиента — 4 секунды с учётом параллельных запросов. Это помогает соблюдать поминутный лимит, но не заменяет лимит аккаунта для нескольких процессов. Приложение и benchmark используют один клиент и одинаковые настройки. В run сохраняются адрес API без ключа, модель, режим JSON, проверка ответа, интервал, таймаут и хеш обоих промптов и инструкции исправления. Ключ и HTTP-заголовки в run не попадают.

Бесплатный API имеет квоты и зависит от интернета. По опубликованным условиям OpenRouter на дату проверки базовая квота бесплатных моделей — 20 запросов в минуту и 50 в день; фактический остаток проверять в аккаунте. По умолчанию дополнительная генеративная проверка выключена ради квоты: полный benchmark обычно требует 15 вызовов, максимально 30 с исправлениями. При её включении обычно нужны 30 вызовов, максимально 45. Детерминированная проверка цитат работает всегда; смысловая оценка человеком обязательна в обоих режимах. Сохранённые прогоны через Ollama относятся к прежнему профилю и не подтверждают качество или доступность нового API. Источники: [модель](https://openrouter.ai/nvidia/nemotron-3.5-super-vl:free), [лимиты](https://openrouter.ai/collections/free-models/).

Команда `go run ./cmd/llm-check` проверяет выбранную бесплатную модель и ключ через API OpenRouter, показывает доступный дневной остаток при наличии его в ответе, затем выполняет один самостоятельный пример на синтетических документах. Она не читает эталоны benchmark. Ключи, ответы API с секретными подробностями и заголовки не печатает.

## Настройки

Все настройки задаются переменными окружения. Ключи и пароли в репозиторий не попадают.

| Переменная | Что задаёт |
|---|---|
| `ADDR` (по умолчанию `127.0.0.1:0`) | Адрес сервера, например `127.0.0.1:0` для выделения свободного порта ОС; в журнале выводится фактический URL после открытия listener |
| `DB_PATH` (по умолчанию `pdd-assistant.sqlite`) | Путь к файлу SQLite |
| `CORPUS_DIR` (по умолчанию `corpus`) | Папка с документами корпуса |
| `ADMIN_LOGIN`, `ADMIN_PASSWORD` | Первый админ |
| `LLM_BASE_URL` (по умолчанию `https://openrouter.ai/api/v1`) | Адрес OpenAI-совместимого API |
| `LLM_API_KEY` | Ключ API; обязателен для OpenRouter |
| `LLM_MODEL` (по умолчанию `nvidia/nemotron-3.5-super-vl:free`) | Имя модели |
| `LLM_TIMEOUT` (по умолчанию `120s`) | Лимит на один запрос к модели, формат Go duration |
| `COOKIE_SECURE` (по умолчанию `false`) | Установить флаг Secure для запуска за HTTPS |
| `LLM_DISABLE_REASONING` (по умолчанию `true`) | Отключать рассуждение: reasoning.enabled=false для OpenRouter, reasoning_effort=none для других API |
| `LLM_JSON_MODE` (по умолчанию `true`) | Запрашивать JSON-объект через response_format |
| `LLM_VERIFY_ANSWER` (по умолчанию `false`) | Второй вызов проверяет и исправляет ответ по тем же источникам |
| `LLM_MIN_INTERVAL` (по умолчанию `4s`) | Минимальный интервал между началами HTTP-вызовов одного клиента; 0s отключает ожидание |

Структура КТ2:

```

cmd/bench/        запуск benchmark (см. spec/tech/rag.md)
internal/web/     обработчики HTTP (Николай)
internal/ui/      встроенные Go-шаблоны, CSS и JS (Пётр)

internal/auth/
internal/store/
internal/search/
internal/llm/
internal/rag/
internal/config/

```

## Как проверяем

- `go test ./...` проходит.

## Контракты КТ2

Контракт интерфейса и инструкции интегратору: `spec/tech/ui.md`. Модуль Go: `github.com/pdd-tech/pdd-assistant`, версия Go не ниже 1.25. Шаблоны и ресурсы встраиваются через `embed`. Для запуска из другой папки можно указать путь к корпусу и БД через окружение. Самостоятельный просмотр UI использует только стандартную библиотеку.

Сервер проверяет CSRF на всех POST (включая вход), авторизацию и роль независимо от интерфейса. Случайный CSRF-токен привязан к анонимной или авторизованной сессии. При входе сессия обновляется, при выходе удаляется. Cookie использует HttpOnly, SameSite=Lax, Path=/ и срок сессии. Анонимная сессия действует 30 минут, авторизованная — 8 часов. Тело формы ограничено 32 КиБ. Поля форм: `login`, `password`, `question`, `csrf_token`. Секреты/сырые ошибки провайдера пользователю не показываются. Вопрос ограничивается 2000 Unicode-символами после TrimSpace; сервер также ограничивает размер тела запроса. При обновлении страницы после создания ученика применяется POST/Redirect/GET.

Общий RAG-сервис используется HTTP-обработчиком и benchmark, чтобы проверять ту же цепочку, что видит пользователь. Контракт: `Ask(ctx context.Context, question string) (Result, error)`, `Result{Answer string, Sources, Ranked []search.Hit, Refused bool}`. `Refused` означает недостаточность контекста; ошибка сети/провайдера — `error`. Пустая выдача не вызывает LLM и считается отказом с сообщением об отсутствии сведений. Валидный вопрос записывается один раз, в том числе при ошибке модели или отказе. При сбое записи сервер возвращает 500. При непустой выдаче модель может отказаться: факт лексического совпадения не доказывает наличие ответа. Результат модели должен иметь проверяемое поле отказа (валидируемая JSON-структура, а не поиск одной фразы в тексте). Тексты источников считаются данными, не инструкциями. В промпт не попадают эталоны benchmark.

Модель не обучаем с нуля и не дообучаем: подключаем готовую LLM через OpenAI-совместимый API. Имя реально проверенной модели и команды её запуска фиксирует Николай. Benchmark ответов без работающей LLM не считается пройденным; preview не используется для измерения качества.

При локальном запуске сначала открываем listener, затем объявляем успешный старт с фактическим адресом. Ошибка занятого порта завершает запуск. Для проверки открываем точный напечатанный URL и сверяем, что страница принадлежит pdd-assistant; одного HTTP 200 недостаточно. Не заменяем 127.0.0.1 на localhost при соседних IPv4/IPv6-сервисах.
